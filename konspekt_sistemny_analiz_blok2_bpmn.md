# Системный анализ — Блок 2: BPMN-нотация

## 1. Что такое BPMN

BPMN (Business Process Model and Notation) — нотация для описания бизнес-процесса как графа: события → задачи → шлюзы → потоки.

**Отличие от sequence-диаграммы:** sequence показывает обмен сообщениями между участниками во времени (технический уровень, вызовы API). BPMN показывает сам процесс как последовательность задач и решений — язык для бизнеса и аналитика, без привязки к конкретным техническим вызовам.

## 2. Базовые элементы

**События (Events)** — круги:
- Начальное событие (тонкая окружность) — что запускает процесс
- Промежуточное событие (двойная окружность) — что-то произошло по ходу
- Конечное событие (жирная окружность) — процесс завершён

**Задачи (Tasks)** — прямоугольники со скруглёнными углами:
- **User Task** — выполняется человеком
- **Service Task** — выполняется системой автоматически
- **Script Task** — автоматический скрипт
- **None Task** — задача без указанного специализированного типа (легитимный тип по спецификации BPMN 2.0, но на практике лучше указывать конкретный тип; если задача — просто финальный результат процесса, часто её вообще не выделяют отдельным элементом, а закрывают через End Event)

**Шлюзы (Gateways)** — ромбы, точки ветвления:
- **Exclusive Gateway (XOR, ×)** — ровно одна ветка из нескольких (аналог `alt` в sequence-диаграмме)
- **Parallel Gateway (AND, +)** — все ветки выполняются одновременно
- **Inclusive Gateway (OR, ○)** — одна или несколько веток по условиям

**Потоки (Sequence Flow)** — стрелки, порядок выполнения.

## 3. Паттерн ветвление → слияние

Если Exclusive Gateway разветвил поток на несколько веток, дальше их можно:
- явно свести через **второй Exclusive Gateway** (слияние) — рекомендуется для читаемости, особенно если веток больше двух или они разной длины;
- либо свести без отдельного gateway, просто в один следующий элемент — формально в BPMN это допустимо, явный сливающий шлюз не обязателен синтаксически.

## 4. Итоговый пример (диаграмма «Баланс счёта с доверенным периодом»)

```
[Start Event]: Пользователь открывает экран баланса
[Service Task]: Проверить доверенный период аутентификации
[Exclusive Gateway]: Доверенный период действителен?
    Да → к слиянию веток
    Нет →
        [User Task]: Пройти аутентификацию
        [Service Task]: Проверить результат аутентификации
[Exclusive Gateway]: Слияние веток
[Service Task]: Получить баланс счёта
[End Event]: Баланс отображён пользователю
```
